### 修改原因

原文只说明把 `.bit`、`.hwh` 传入 PYNQ 后参考 `exp_PL.ipynb`，没有说明当前 Kria 的 Overlay 文件名、DMA 调用、分类服务和 TonyPi 的访问方式。

1. 将以下文件放入 Kria 的同一部署目录：

   ```text

   ```

   当前部署目录为：

   ```text

   ```

2. 在 Kria 终端检查是否有其他应用占用 FPGA：

   ```bash

   ```

   ```bash
   cd /root/jupyter_notebooks/fpga_flower_server
   python3 -u fpga_server_api_ready.py
   ```

   出现 `Overlay ready.` 和 `Running on http://192.168.31.81:8080` 表示当前仓库配置下服务已经启动。服务运行期间保持终端开启。

4. 服务启动时通过 `Overlay("design_1_wrapper.bit")` 加载 `.bit` 和同名 `.hwh`，然后取得：

   ```python
   overlay.axi_dma_0.sendchannel
   overlay.axi_dma_0.recvchannel
   ```

   输入缓冲区为 `3 × 28 × 28` 的 `float32` 数据，输出缓冲区为 12 个 `float32` 分类结果。数据链路为：

   ```text
   bit + hwh
       ↓
   PYNQ Overlay
       ↓
   AXI DMA 发送通道
       ↓
   CNN FPGA IP
       ↓
   AXI DMA 接收通道
       ↓
   Python 读取 12 类结果
   ```

5. 当前分类接口为：

   ```text
   POST http://192.168.31.81:8080/predict
   Content-Type: multipart/form-data
   表单字段：image
   ```

   成功响应包含 `flower_api`、`flower_cn`、`class_index` 和 `confidence`。直接使用浏览器或 `curl` 对该地址发送 GET 请求时返回 `405 Method Not Allowed`，表示服务可达，但分类必须使用 POST 请求。

## 3.5 现实识别

### 修改原因

原文关于采集现实数据、处理光照和视角变化、提高鲁棒性的原则仍然有效；只需补充当前 TonyPi 获取屏幕图像并送入 Kria 分类的实际方式。

### 修改后内容

保留本节现有理论说明，在其后补充以下操作流程：

1. 图像由 TonyPi Raspberry Pi 上的相机采集。当前代码使用 TonyPi 相机接口连续获取画面，不再使用旧机器人或旧 PYNQ Notebook 直接获取机器人图像。

2. 在画面中检测屏幕四边形，进行几何和白色区域过滤，并把屏幕与其左上方的 1～36 号 AprilTag 绑定。通过透视变换提取 `28 × 28` 屏幕区域作为分类图像。

3. TonyPi 将该图像编码为 JPEG，以 multipart 表单字段 `image` 通过 HTTP POST 发送到 Kria 的 `/predict` 接口。

4. Kria 服务将图像转换为 `28 × 28` RGB 数据，按通道标准化，通过 DMA 送入 FPGA CNN IP，并返回 12 类花朵的类别和置信度。

当前识别链路为：

```text
TonyPi 相机
    ↓
检测 Screen 并与 AprilTag 绑定
    ↓
透视裁剪为 28 × 28 图像
    ↓
HTTP POST image
    ↓
Kria /predict
    ↓
DMA + CNN FPGA IP
    ↓
返回花朵类别与置信度
```

### 3.3.3 改变花的种类

#### 修改原因

原文通过 `192.168.1.254/api/change/...` 直接发送 HTTP GET 请求。当前系统改为 TonyPi 左手靠近对应 Worker 后，通过 ST25DV04 NFC 邮箱交换请求和响应。

#### 修改后内容

将本节的平台相关步骤替换为：

1. TonyPi 在确认当前 Screen 和花朵类别后，站立并举起左手，使 NFC 标签靠近对应 Worker。

2. 当前程序调用 `robotall.send_request()`，写入 `team`、`secret`、`robot_id`、`worker_id`、`from_flower` 和 `to_flower` 等信息，并等待 Worker 响应。当前约定中 AprilTag ID、`screen_id` 和 `worker_id` 应一致。

3. 无论交互成功或失败，机器人都恢复 `stand`。只有收到与本次请求序号及 Worker ID 匹配的成功响应，才认为花朵已经改变。

4. 删除原 `/api/change/:name/:secret/...` URL 及对应 GET 示例。HTTP `requests` 库在本实验中仍用于 TonyPi 向 Kria 发送分类图像，但分类请求应为 multipart POST：

   ```python
   import cv2
   import requests

   ok, encoded = cv2.imencode(".jpg", crop_28x28)
   if not ok:
       raise RuntimeError("图像编码失败")

   files = {"image": ("crop_28x28.jpg", encoded.tobytes(), "image/jpeg")}
   response = requests.post(
       "http://192.168.31.81:8080/predict",
       files=files,
       timeout=4.0,
   )
   result = response.json()
   ```

原文关于 HTTP 方法、状态码、JSON 和 `requests` 库的一般介绍仍然适用，不作重写。
