### **3.1 地图建模**
在进行机器人路径规划之前，需要将比赛场地转换为机器人能够使用的地图模型。本实验场地为边长约 294.1 cm 的正方形，可以在场地平面上建立二维世界坐标系，并使用 $(x,y)$ 表示场地中的位置。


注：场地与 XY 坐标系示意图可参见图 1，且相关场地信息的 AprilTag 世界坐标已经在 load_pos.py 中给出

图 1: 场地、定位点、白色障碍物、XY 坐标系示意图

![](.png)

场地上有定位点 tag 与障碍物 tag 两种 Apriltag。

- 定位点 tag 共有 18 个，都贴在地面上，给出了对应的 (x,y) 坐标与 id（也即认为世界坐标系下 Z 轴方向的分量全都是 0）（给出的坐标是每个 tag 左上角顶点的坐标，在实际定位的时候需要考虑 tag 是 5*5cm 的正方形，计算出 4 个角的坐标，详见 _expand_ ()函数）。定位点 tag 用于给定位提供信息，无需参与到地图建模中去。

- 障碍物 tag 共有 9 组，每一组内有 4 个，表示贴在同一个白色障碍物（占地面积25*25cm）的四个竖直面上。每组的第一个对应着该组四个 tag 中位于左上角的 tag（结合代码理解），之后的三个从上往下看呈逆时针方向。同样的，每个坐标皆是某个 tag 的4 个角中左上角顶点的坐标，需要通过 _expand_ _2() 函数计算该 tag4 个角的坐标，并加入 Z 方向（39.8cm）的坐标，实现对白色障碍物上 tag 在世界坐标系中的位置存储。

实验中需要各位同学将场地长宽信息与障碍物信息建模为二维的地图，地图的数据结构请大家自行选择。基于此地图可以即插即用地与常用路径规划算法进行结合。

### **3.2 定位与机器人动作控制**

本次实验希望同学们可以基于前面实验的内容实现机器人在世界坐标系下的定位，并根据机器人当前位置与目标位置之间的关系，自行实现路径规划与动作控制。因此前面几次实验的内容也至关重要，较为准确的定位与动作控制可以将问题简化为路径规划算法本身。

 - **AprilTag** **识别** ：基于实验二的内容，机器人可以较为鲁棒地识别出 AprilTag，为后续计算位置做好准备。

 - **摄像头标定与机器人定位** ：基于实验三的内容，机器人需要能够获得自己当前的位置与朝向。场地中的地面定位 Tag 与白色障碍物上的 Tag 均给出了对应的世界坐标，因此均可以作为机器人定位的依据。相关 AprilTag 世界坐标存储在 load_pos.py 中。

 - **动作控制** ：理想情况下，机器人在实际场地二维平面上不同坐标点之间的移动能够较为准确地通过已有动作完成。TonyPi 的移动主要通过动作组实现，包括前进、后退、左转、右转等动作。实际程序中可以根据机器人与目标点之间的距离和角度选择合适的动作，并将这些动作进一步封装为前进、转向等基本运动函数。

<u>注：由于机器人实际执行动作时会受到地面摩擦、机器人个体差异、电池电量等因素影响，同一个动作每次产生的实际位移和转角可能存在一定误差。因此需要通过实际测试了解各个动作与机器人在地图中运动距离之间的关系，并根据实际机器人进行适当调参。实战中建议各位同学记好调试所用机器人的编号或特征。不同机器人之间可能存在一定差异，因此即使使用完全相同的动作参数，最终运动距离和转向角度也可能有所不同。</u>

此外，在机器人运动过程中应尽量避免完全依赖动作次数推测当前位置。机器人执行一定距离后，可以重新利用 AprilTag 获取当前位置和朝向，并根据实际定位结果修正后续运动，从而减小长距离行进时产生的累计误差。

算法的鲁棒性可能会被硬件的不确定性给制约，这是业界工程上也常常面临的困境，解决办法无非进一步提高算法鲁棒性、提高硬件精度、算法与具体硬件捆绑，本次实验我们选取最简单的第三种办法即可。

下面是一个简单的函数样例。通过实际测试可以获得机器人单次前进动作对应的大致移动距离，并根据目标距离决定执行动作的次数。

```python
def go_straight(self, distance):
    # 代码逻辑仅供参考，请大家自行设计并调参。

    if distance > 45:
        # 距离较远时连续执行较快的前进动作
        num = int(np.floor(distance / 3.5))

        print(f"run forward_fast for {num} time(s)")

        self.motion.run(
            "forward_fast",
            times_override=num
        )

    else:
        # 距离较近时减少单次执行步数，
        # 避免机器人越过目标位置
        num = max(1, int(np.floor(distance / 3.5)))

        self.motion.run(
            "forward_fast",
            times_override=num
        )
```

<u>注：根据往年实验的经验，实验四在实现上繁琐的地方更多是动作控制的部分，就算对特定机器人通过不断的调试获得了较为不错的效果，但是场地内不同局部区域、机器人电量等因素仍然会给动作控制带来一定的不确定性。众多因素会带来误差，在进行长距离行进的时候，该误差可能会累积到一个无法忽视的程度，这意味着直接根据路径规划给出从起始点到目标点的路径并且让机器人一条路走到底的算法极大概率会行不通，如果没能结合当前定位做出即时的调整，机器人很可能会在途中越走越歪，最后碰壁。因此动作调用之间还需要代码方面对于 **负反馈与闭环控制** 的优化，建议大家定期更新机器人当前坐标与朝向，基于当前的信息可能需要调整最开始的规划路线。</u>

一个简单的思路如下，供大家参考：

1. 输入：起始点 $A$、终点 $Z$

2. 在最开始规划出一条路线 $\mathcal{L}_0$，途径 $A \rightarrow B \rightarrow C \rightarrow \cdots \rightarrow Z$

3. 在途经点 $B$ 处，获得机器人当前实际坐标 $B'$ 与朝向，并进行判断：

   3.1. $\|B-B'\|_2 \leq \epsilon$：新路线 $\mathcal{L}_1 \subset \mathcal{L}_0$，且 $\mathcal{L}_1: B \rightarrow C \rightarrow \cdots \rightarrow Z$

   3.2. $\|B-B'\|_2 > \epsilon$：已偏离原规划路线，重新规划新路线 $\mathcal{L}'_1$，则 $\mathcal{L}'_1: B' \rightarrow \cdots \rightarrow Z$

4. 基于新的路线行走，并对后续途经点重复 3 的过程

5. 抵达终点 $Z$

在机器人重新定位时，还需要考虑摄像头当前视野中可能没有可用 AprilTag 的情况。如果暂时无法完成定位，可以加入转动机器人、调整观察方向或进行小范围移动等逻辑，重新寻找可用的 AprilTag。

将硬件方面的动作控制与算法方面的路径规划进行结合，这是实验四最为考验的地方，既是机器人繁琐之处，也是其魅力所在。祝同学们顺利！
