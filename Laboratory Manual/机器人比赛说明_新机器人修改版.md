# 基础考核及比赛规则——新机器人修改版

本文档基于《机器人比赛说明.md》Ver1.1 修改。比赛时间、计分、扣分、晋级人数、轮次和换花机会数尽量保持原规则；技术实现改为 TonyPi + HTTP FPGA 分类 + NFC 注册/换花。日期、花卉数量等如与当届通知不一致，以课程最终比赛通知为准。

## PART.I 基本说明

- 最终比赛将使用五次小实验的代码内容，请先保证之前所有实验完成并验收。
- 比赛场地与实验四基本完全相同，比赛时间为 10 分钟，每支队伍由两人组成。在基础考核中，要求每支队伍在 10 分钟内至少将 10 个屏幕上的花换为目标花；每支队伍都要完成基础考核。晋级规则见 PART.V。
- 每支队伍的目标均为在 AprilTag 定位帮助下，使场地中拥有更多本队目标花卉，从而获得更高得分。
- 当前系统存在两条独立通信链路：

  ```text
  FPGA 分类：TonyPi / Client → HTTP → FPGA 服务体系 → Kria KV260 → 分类结果

  比赛控制：TonyPi ↕ NFC ↕ Start / Worker
  ```

  FPGA Artifact 上传和分类使用 HTTP；机器人身份注册和换花请求使用 NFC。HTTP 不是换花协议，NFC 也不是 FPGA 上传协议。

## PART.II 行动流程

- 在比赛开始前，每个机器人身体四个方向会贴上 ID 大于 90 的 AprilTag，用于其他机器人识别和避障。
- 在比赛开始前 30 秒，机器人在 Start 处通过 NFC 注册，Start 返回本局目标花卉和任务信息，并按比赛安排确定随机起点。
- 开始比赛后，所有队员必须站到指定位置，不能再与机器人通信。
- 比赛过程中，所有显示屏会先用 8 种花卉中非目标花卉填满。
- 机器人在给定场地中自由探索，直到比赛结束。
- 机器人可在对应 Worker 处通过 NFC 请求更换目标位置的花卉，详细规则见 PART.III。
- 时间结束时，得分最高的机器人获胜，得分规定见 PART.IV。

### 比赛前机器人注册

当前注册不再使用旧上位机 HTTP 注册地址。标准流程为：

```text
TonyPi 到达 Start
    ↓
stand
    ↓
举起左手
    ↓
写入 IDENTITY 请求
    ↓
左手 NFC 靠近 Start 读卡区
    ↓
Start 读取并校验 TEAM / SECRET / ROBOT_ID
    ↓
Start 写回本局任务
    ↓
TonyPi 读取注册响应
    ↓
stand
```

简化测试代码与 `robot_code/test/action_identity_test.ipynb` 一致：

```python
import time

from robotall import act, register_robot

TEAM = "red"
SECRET = "1234"
ROBOT_ID = "red-1"
SCAN_TIMEOUT_S = 0

act("stand")
try:
    act("lift_left_hand", stand=False)
    time.sleep(0.5)
    result = register_robot(
        team=TEAM,
        secret=SECRET,
        robot_id=ROBOT_ID,
        clear_first=True,
        read_response=True,
        wait_response=True,
        scan_timeout_s=SCAN_TIMEOUT_S,
        verbose_wait=True,
    )
    if not result["ok"]:
        raise RuntimeError("没有收到有效的 Start 身份注册响应")
finally:
    act("stand")
```

- `TEAM`：课程分配的队伍标识。
- `SECRET`：课程分配的队伍凭据，不应写入公开提交。
- `ROBOT_ID`：本台 TonyPi 的机器人标识。
- `SCAN_TIMEOUT_S`：等待 Start 扫描和响应的时间；测试 Notebook 中 `0` 表示不限时间，便于人工移动机器人到读卡区。

只有收到 `result["ok"] == True` 的有效响应，才认为注册完成。目标花等本局任务信息由 Start 响应提供，不能在正式比赛程序中自行假定。

### 比赛完整数据链路

```text
比赛开始
    ↓
TonyPi 前往 Start
    ↓
NFC 注册并获得目标花
    ↓
AprilTag 定位
    ↓
路径规划并移动至 Screen / Worker
    ↓
相机获取屏幕区域
    ↓
HTTP FPGA 分类
    ↓
得到当前花 from_flower
    ↓
是否已经是目标花？
    ├── 是 → 记录并跳过换花
    │
    └── 否
         ↓
      TonyPi 站立并举起左手
         ↓
      NFC send_request
         ↓
      Worker 校验并写回结果
         ↓
      TonyPi 读取成功 / 失败响应
         ↓
      继续下一目标
```

各实验在总流程中的位置为：实验一负责启动和基础操作，实验二负责 AprilTag，实验三负责定位，实验四负责导航，实验五负责 FPGA 分类；比赛程序负责 NFC 注册、NFC 换花和综合控制。

## PART.III 更换花卉流程及规则

- 对于所有位置的花卉，每个机器人共有 5 次机会更换。
- 当前正式方案只有 NFC 换花。旧 HTTP GET 换花接口不再使用。
- 机器人到达目标 Screen / Worker 后，应先通过 FPGA 分类取得当前花卉，再准备换花请求：

  ```text
  到达目标 Worker
      ↓
  确认目标 AprilTag 与 Screen 绑定
      ↓
  FPGA 分类得到 from_flower
      ↓
  准备 to_flower
      ↓
  stand → 举起左手
      ↓
  左手 NFC 靠近 Worker
      ↓
  send_request()
      ↓
  Worker 校验 TEAM / SECRET / ROBOT_ID / WORKER_ID / from_flower
      ↓
  Worker 写回成功或失败结果
      ↓
  TonyPi 读取结果 → stand
  ```

- 当前机器人实现明确规定：

  ```text
  AprilTag ID == screen_id == worker_id
  ```

  因此请求中的 `WORKER_ID` 必须等于当前目标 Screen 绑定的 AprilTag ID。不得根据旧指导书另行猜测映射。

- 简化测试代码与 `robot_code/test/action_change_flower_test.ipynb` 一致：

  ```python
  import time

  from robotall import act, send_request

  TEAM = "red"
  SECRET = "1234"
  ROBOT_ID = "red-1"
  WORKER_ID = 12
  FROM_FLOWER = "main"
  TO_FLOWER = "bailianhua"
  SCAN_TIMEOUT_S = 0

  act("stand")
  try:
      act("lift_left_hand", stand=False)
      time.sleep(0.5)
      result = send_request(
          team=TEAM,
          secret=SECRET,
          robot_id=ROBOT_ID,
          worker_id=WORKER_ID,
          from_flower=FROM_FLOWER,
          to_flower=TO_FLOWER,
          clear_first=True,
          read_response=True,
          wait_response=True,
          scan_timeout_s=SCAN_TIMEOUT_S,
          verbose_wait=True,
      )
      if not result["ok"]:
          raise RuntimeError("没有收到有效的 Worker 换花响应")
  finally:
      act("stand")
  ```

- 参数含义：

  - `TEAM`：队伍标识；
  - `SECRET`：队伍凭据；
  - `ROBOT_ID`：机器人标识；
  - `WORKER_ID`：目标 Worker 标识，必须与目标 `screen_id` 和 AprilTag ID 一致；
  - `FROM_FLOWER`：FPGA 分类得到的当前花卉 API 名称；
  - `TO_FLOWER`：Start 注册响应分配的本队目标花卉；
  - `SCAN_TIMEOUT_S`：等待 Worker 扫描和响应的时间。

- 只有收到与本次请求匹配且 `result["ok"] == True` 的 Worker 响应，才认为换花成功。超时、无响应或 `ok == False` 都不能标记为已更换。
- 若该位置的原始花卉种类识别正确，则正常更换为拟更换的花卉种类，且不消耗更换机会。
- 若花卉种类不正确，则消耗一次更换机会，且花卉种类不更换。
- 花卉 API 名称沿用：`bailianhua chuju hehua juhua lamei lanhua meiguihua shuixianhua taohua yinghua yuanweihua zijinghua`。

## PART.IV 得分失分细则

- 任意时刻，将某位置的非目标花卉正确更换为目标花卉，得 1 分。
- 比赛结束时，赛道上所有屏幕中，每有一个该机器人对应的目标种类花卉，得 3 分。
- 任意时刻错误识别某位置花卉，失去 1 分。
- 任意时刻机器人因摔倒等原因需要重启或复位时，需要回到自身起点，等待 10 秒后再次出发。

上述计分和扣分规则沿用原文；若当届系统对 NFC 失败类型或重试次数有进一步规定，以课程最终比赛通知为准。

## PART.V 比赛及排名流程

- 完成基础考核后，按照排名取前 8 支队伍进行比赛。
- 排名依据优先级如下：

  1. 得分高的队伍排名靠前。基础考核中，助教会随机三次将身体四个方向粘贴 ID 大于 90 的 AprilTag 的测试机器人放置于每队机器人行进方向前方约 10～20 cm 处约 15 秒；若测试机器人在 15 秒内被撞倒，则最终得分扣 2 分。正式比赛无此扣分限制。
  2. 得分相同时，目标花卉留存数量多的队伍排名靠前。
  3. 目标花卉留存数量相同时，识别错误次数少的队伍排名靠前。

- 比赛场地中有四支队伍，比赛时间为 10 分钟；每个机器人身上会贴 ID 大于 90 的 AprilTag 作为避障标识。

1. 比赛开始前 30 秒，各 TonyPi 在 Start 处通过 NFC 注册并取得目标花卉及随机起点，随后等待开始信号。
2. 共有 8 支队伍参加比赛，进行两轮比赛；每轮分为两场，每场 4 支队伍，即每支队伍有两次参赛机会。
3. 两轮比赛结束后，取两轮中的最好成绩，按积分排名，前 4 名进入决赛。
4. 决赛前两名再进行一轮比赛争夺冠军和亚军；后两名再进行一轮比赛争夺季军。

## PART.VI 基础考核日期及比赛日期

- 原规则中的安排为：基础考核时间为第十四周周三下午、周四下午、周五下午，以及第十五周周三下午、周四下午；比赛时间为第十五周周五下午。
