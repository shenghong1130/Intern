三条不能混淆的“左侧”：视觉绑定使用屏幕图像左侧 AprilTag；实体交互使用屏幕左侧约 5 cm reader；机器人使用左手读卡。三者当前物理方向一致，但在代码中属于独立判断，不能相互替代。

2. 地图、Screen 与坐标语义

场地坐标以 cm 为单位。每个 Screen 明确区分观察位姿和实体交互位姿：

Screen
├─ center_xy                  屏幕中心
├─ normal_xy / normal_yaw    屏幕平面指向可见正面的单位法向
├─ observation_xy            约 48 cm 的视觉观察点
├─ screen_left_tangent_xy     站在正面看屏幕时的屏幕左方向
├─ reader_xy                 屏幕中心左侧约 5 cm
├─ interaction_xy            机器人身体中心的交互目标
├─ interaction_yaw_deg       身体正面朝向屏幕
├─ interaction_staging_xy    A* 导航使用的近屏幕预备点
└─ worker_id                 显式 screen → Worker 映射
法向已按现有代码语义确认： normal 从屏幕平面指向可见正面，因此机器人正对屏幕的身体 yaw 是 normal_yaw + 180°，而不是 normal_yaw。

交互几何

n = normalize(normal_xy)                         # 屏幕 → 正面
left = (n.y, -n.x)                              # 观察者看到的屏幕左侧
reader = center + left * sensor_left_offset_cm
body_lateral = sensor_left_offset_cm - left_hand_body_offset_cm
interaction = center + n * interaction_distance_cm
                     + left * body_lateral
interaction_yaw = atan2(n.y, n.x) + 180°

left_hand_body_offset_cm 是左手相对身体中心沿身体左侧的真实偏移；仓库没有可靠机械尺寸，默认 0，仅作为待现场标定入口，不代表精确测量值。

3. AprilTag 定位

localize_scan() 依次转动头部，检测 AprilTag，并由 Localizer 更新 RobotPose。定位成功时仍可通过 harvest_during_localize() 顺便识别屏幕，但该函数只调用 observe_frame() 更新观察，无法触发 Worker 事务。

RobotPose 缺失、置信度不足或超过 interaction_pose_max_age_s 时，交互安全门必定拒绝。
每个扫描角度
→ 控制头部舵机
→ 等待稳定并丢弃旧帧
→ AprilTag detect
→ 质量门：面积 / 画面边缘 / ID
→ solvePnP
→ 场地范围检查
→ 更新 RobotPose

5. 目标选择与导航

choose_next_screen() 根据 Screen 状态选择不同目标：

状态导航目标目的
UNKNOWN / FAILEDobservation_xy观察、分类与投票
NEEDS_CHANGEinteraction_staging_xy进入最终实体对准
ALREADY_TARGET / CHANGED不再作为普通目标已完成或无需换花

长距离部分继续复用 action-level A*、普通 A*、碰撞/无进展检测、动态障碍和边界恢复。15 cm 交互点没有冒充原观察点；A* 先到 staging point，再由小动作完成贴近对准。

6. Phase A：视觉识别与投票

发现 Screen / AprilTag 绑定（花朵屏幕左上附近的 1～36 号 Tag）
→ FPGA classify
→ 置信度检查 / 多帧 vote
→ store_flower_observation()
   ├─ flower == target → ALREADY_TARGET（不举手、不请求）
   └─ flower != target → NEEDS_CHANGE（仅排入实体交互）

observe_frame()、finalize_harvest_votes()、harvest_visible()、harvest_opportunistic()、scan_after_turn() 和 harvest_during_localize() 都只负责观察。

远距离识别成功 ≠ 换花授权。 分类结果只说明 Screen 当前大概率显示什么花。
屏幕候选四边形
→ 顺序固定为 TL / TR / BR / BL
→ 寻找左上角附近 Tag
→ Tag ID 在 1～36？
→ Tag center 位于屏幕 center 左侧？
→ 距离小于 max(tag_bind_max_px, diagonal × ratio)？
→ 选择距离 TL 最近的 Tag
→ map.screens 中存在该 ID？
→ 绑定为 screen_id

7. Phase B：近距离实体换花

NEEDS_CHANGE
↓
navigate_to_interaction_pose() → staging XY + target yaw
↓
align_for_screen_interaction()
  ├─ 重新 AprilTag 定位
  ├─ yaw 不合格 → 微转
  ├─ lateral 不合格 → 左右平移
  ├─ distance 不合格 → 小步前进/后退
  └─ 再定位、再检查（最多 N 步）
↓
TaskManager 最终 safety gate
↓
RobotInteractionClient 底层 safety gate
↓
实体事务

evaluate_interaction_pose() 集中检查以下全部条件：

pose 存在、够新、置信度满足配置
flower 已可靠识别且不是目标花
distance 平面法向距离约 15 cm
yaw 身体朝向屏幕，误差在容差内
lateral 左手对应左侧读卡区
mapping screen_id 有显式 worker_id

任何条件失败都不会举手或发送请求。上层对准完成后检查一次；底层交互函数在举手前检查，并在发送前再次检查，防止状态机错误绕过。

8. robotall / Worker 原子事务

旧 HTTP ApiClient 已淘汰。正式流程严格采用提供的 notebook 调用方式：

act('stand')
try:
    act('lift_left_hand', stand=False)
    wait 0.5 s
    safety_gate()                 # 举手后的第二次检查
    send_request(
        team, secret, robot_id, worker_id,
        from_flower, to_flower,
        clear_first=True,
        read_response=True,
        wait_response=True,
        scan_timeout_s=配置值,
        verbose_wait=True,
    )
finally:
    act('stand')

只有 result['ok'] 为真才标记 CHANGED。ok=False、超时或异常均恢复为 NEEDS_CHANGE，保留后续重试；finally 始终收手站立。事务期间硬件层禁止普通导航动作。

worker_id 不默认等于 screen_id。 当前资料只有 notebook 的 Worker 12 样例，不能证明通用一一映射，因此必须在 interaction.worker_mapping 中显式配置；缺映射时安全拒绝。

9. 路过顺手识别

路过 / opportunistic / passby
→ 发现屏幕
→ classify / vote
→ 更新 Screen 花朵缓存
→ 最多标记 NEEDS_CHANGE
→ 不举手、不 send_request

本轮只完成必要的安全重构，保留现有路过扫描策略；其完整最优调度策略留待后续优化。它不具有实体换花能力。
