2. 初始定位决策树（保持原行为）

LOCALIZE / initial_localize()
  • 按原 pan 顺序 [100,135,65,155,45] 拍摄、检测 AprilTag，并由原 Localizer 求世界 pose。
  • 获得有效 pose？
    • 是：写入状态并进入最近目标选择。
    • 否：继续原搜索动作、失败计数、边界过滤和重新定位流程。
  • 定位帧允许更新屏幕四边形与左上方 Tag 的几何绑定，但 不裁剪花朵、不分类、不换花。

load_pos.py、localizer.py、地图坐标、Tag 坐标和初始定位判断均未改变。

3. 从 Tag 平面构造四向 15 cm 位姿

configure_cardinal_task_targets()
  • 每四个 Tag 属于同一四方形；从该组 Tag 四角坐标包围盒得到建筑物中心，不修改原坐标。
  • Tag 四角 X 基本相同：这是西/东侧面；比较 Tag 中心 X 与建筑物中心 X。
  • Tag 四角 Y 基本相同：这是南/北侧面；比较 Tag 中心 Y 与建筑物中心 Y。
  • 外法向严格量化为 (-1,0)、(+1,0)、(0,-1)、(0,+1)，不使用斜向中心差。
Tag 面外法向 nTag 正前方基础点身体目标 yaw
WEST / 西侧(-1, 0)(cx − 15, cy)0°
EAST / 东侧(+1, 0)(cx + 15, cy)-180°（等价 180°）
SOUTH / 南侧(0, -1)(cx, cy − 15)+90°
NORTH / 北侧(0, +1)(cx, cy + 15)-90°
C = Tag center n = quantized outward normal tag_front_xy = C + 15cm × n screen_left_tangent = (ny, -nx) body_lateral = sensor_left_offset_cm - left_hand_body_offset_cm task_target_xy = tag_front_xy + body_lateral × screen_left_tangent target_yaw = atan2(-ny, -nx)

tag_front_xy 是纯粹的 Tag 正前方 15 cm 基础点；task_target_xy 是叠加既有左手/读卡器切向补偿后的机器人身体点。补偿只改变切向位置，不改变 15 cm 法向距离和四向 yaw。

4. 最近未处理目标选择

stable_key = (distance(robot.pose.xy, screen.task_target_xy), screen_id)
SELECT_NEAREST_TARGET / choose_nearest_screen()
  • 只从未完成目标中选择；CHANGED、ALREADY_TARGET、FAILED 不再入选。
  • 距离使用当前最新 pose 到 15 cm 身体目标 task_target_xy，不再使用旧 34 cm target_xy。
  • 同距离按 screen/tag ID 升序，保证稳定排序。
  • 锁定后，途中看到其他屏幕或 Tag 只更新几何信息，不能抢占目标。
  • 每处理完一个目标，清锁并用最新定位重新计算，不生成固定路线。

Dashboard 记录 screen/tag ID、面方向、外法向、15 cm 基础点、补偿后身体点、目标 yaw、当前距离和完整排序结果。Worker 仍由显式映射解析，绝不假设 screen_id == worker_id。

5. 常规接近与最终闭环对准

NAVIGATE_TO_APPROACH

A*、action-level A*、障碍膨胀、碰撞/无进展和边界恢复保持原样。约 34 cm screen.target_xy 仅作为地图自由区的内部安全接近 waypoint。

到达该点不能设置 ARRIVED，不能裁花或分类。

FINAL_ALIGN_15CM

接近后通过 AprilTag 反复更新 pose，按顺序用小转、左右平移、微前进或后退修正 yaw、切向误差和法向距离。

地图无法直接规划到 15 cm 时，也不修改地图或把安全点冒充最终点。

navigate_to_task_pose(screen)
  • 常规导航到 screen.target_xy；此时强制 arrived_at_target=False。
  • 进入 FINAL_ALIGN_15CM，调用 align_for_screen_interaction(..., geometry_only=True)。
  • 到达几何门 检查：目标锁仍由上层保持、pose 存在、置信度达标、pose 新鲜、法向距离为 15 cm±容差、横向误差在容差内、yaw 与四向标准值误差在容差内。
  • 几何门通过？
    • 是：上层设置 ARRIVED_AT_TARGET，允许拍摄。
    • 否：继续局部微调；超过对准步数则当前导航失败，绝不分类。

普通导航动作选择（保持原运动模型）

world delta → robot-local components forward = dx·cos(yaw) + dy·sin(yaw) lateral = -dx·sin(yaw) + dy·cos(yaw) progress = old waypoint distance - predicted waypoint distance
情况选择保护
局部 forward 有足够进展forward_fast，按剩余距离与置信度决定次数地图线段、边界、停止预留距离
局部 lateral 更有效strafe_left_fast / strafe_right_fast预测线段可通行且产生最小进展
无可行平移动作向 waypoint 转身；大误差用 large，小误差用 fast边界感知转向与 turn progress watchdog
最终 15 cm 对准micro turn、单步 lateral、forward_micro/back_fast每步后重定位并重新检查几何门

6. 通过到达几何门后才分类

ARRIVED_AT_TARGET → CAPTURE_TARGET_SCREEN
  • classifier_gate_open() 同时要求：当前目标锁匹配、ARRIVED 标志有效、状态允许且 evaluate_arrival_geometry() 通过。
  • 拍摄帧若得到新视觉 pose，会再次检查几何门；如果位置或 yaw 已漂移，先在当前目标附近重新对准，不调用分类器。
  • 屏幕候选必须绑定当前锁定 screen/tag ID；其他候选被忽略。
  • 只有 classify_arrived_target() 能调用 FPGA 分类器；原 28×28 裁剪、置信度、投票和最小票数逻辑不变。
  • 稳定花朵 == target_flower？
    • 是：ALREADY_TARGET，不举手、不请求 Worker，目标完成。
    • 否：NEEDS_CHANGE，在当前 15 cm 位姿进入完整换花门。

--dry-run 仍不连接真实相机、动作、FPGA 或 Worker；--skip-change/--skip-api 仍允许真实定位、导航和分类，但不真实举手或发送请求。
