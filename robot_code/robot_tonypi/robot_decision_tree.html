2. 初始定位决策树（保持原行为）

LOCALIZE / initial_localize()
  • 无 pose 时按原顺序扫描头部 pan：[100,135,65,155,45]；靠边过滤朝场外视角。
  • 每个角度拍照并检测 AprilTag；ID、边缘距离和面积通过原质量门后，以 solvePnP 求位姿。
  • 按头部 pan 修正身体 yaw，扣除相机前置偏移，并执行原场地范围判断。
  • 得到 pose？
    • 是：写入 HIGH pose，清零失败计数，保持原进展检查；同帧只更新屏幕/左上 Tag 几何绑定，不裁花、不分类。
    • 看到 Tag 但无 pose：增加定位失败计数。
    • 完全无 Tag：增加 no-tag 计数。
  • 失败后仍按原 startup_search_actions 搜索；转身后的 scan_after_turn() 仍可定位和更新几何绑定，但不分类。

未修改 localizer.py；扫描顺序、头部动作、PnP、置信度、恢复条件、坐标系及 yaw 定义保持不变。

3. 最近未处理 Tag 选择

distance = hypot(robot.x - screen.target_xy.x, robot.y - screen.target_xy.y) stable_key = (distance, screen_id /* binding Tag ID */)
SELECT_NEAREST_TARGET / choose_nearest_screen()
  • 候选来自 MapModel.unfinished_screens()；地图排除 ID、CHANGED、ALREADY_TARGET、FAILED 不再入选。
  • 按当前世界 pose 到每个 target_xy 的二维欧氏直线距离升序。该点默认在屏幕正前方 34cm，是直达并拍摄的目标，不是旧的远距离观察停靠点。
  • 同距离按 screen_id（屏幕绑定 Tag ID）升序，结果稳定可复现。
  • 锁定 current_target_screen_id 后，途中看到其他屏幕不能抢占。
  • 当前目标处理后清锁，并从机器人最新 pose 重新计算，绝不预生成固定访问序列。

screen_id 来自屏幕左上绑定 Tag；worker_id 只通过显式 interaction.worker_mapping 解析，绝不假设与 screen/tag 相等。

4. 直接导航、路径规划与动作选择

NAVIGATE_TO_TARGET

navigate_to_screen(screen) 始终把当前锁定屏幕的 target_xy 作为任务目标，单个目标最多执行 max_steps_per_target=80 个导航决策步。

任务层不会插入 pass-by、opportunistic、周期扫描或观察识别停靠点；底层为了转向、分段行走、重新定位和安全恢复而产生的动作步骤仍然保留。

途中视觉：geometry-only

导航引发重新定位或转身扫描时，observe_transit_bindings() 调用 ScreenDetector.detect(..., extract_crops=False)，只检测屏幕四边形并绑定屏幕左上附近的 1～36 号 AprilTag。

途中不能生成 28×28 crop，不能调用 FPGA、投票或写入花朵状态，也不能因为看到其他屏幕而切换当前目标。

4.1 navigate_to_screen() 每一步的完整决策

NAVIGATE_TO_TARGET：开始一个导航决策步
  • 当前 pose 是否存在？
    • 不存在：执行 localize_scan()；定位失败时调用 no-tag 恢复判断。
    • 恢复后仍无 pose：当前目标导航失败。
    • 存在：继续使用当前世界坐标和 yaw。
  • collision_recovery_pending 是否成立？
    • 成立：执行 recover_toward_field_center("forward_no_progress", backoff=True)，完成后进入下一导航步。
    • 不成立：继续计算目标距离。
  • 计算 dist = distance(robot.pose.xy, screen.target_xy)。
  • dist ≤ arrival_radius_cm（默认 23cm）？
    • 否：继续安全检查和路径规划。
    • 是：目标身体 yaw 使用 screen.interaction_yaw_deg，计算 yaw_diff。
    • yaw_diff ≤ arrival_yaw_tolerance_deg（默认 30°）？
      • 否：调用边界感知转向，转正后重新判断，不能提前分类。
      • 是：记录 arrived_at_target，导航成功并进入 ARRIVED_AT_TARGET。
  • 墙边预检查：若地图判断机器人在当前朝向上离墙小于 safe_wall_distance_cm，先执行恢复，不向目标继续前进。
  • 规划路径：调用 plan_navigation_path(pose, target_xy)，再由 select_navigation_waypoint() 选本轮可执行的前视点。
  • 根据 waypoint 计算世界目标 yaw、当前 yaw 差，并发布路线到 Dashboard。
  • choose_translation_action() 是否产生前进或平移候选？
    • 有：执行预计能最大幅度缩短 waypoint 距离的平移动作。
    • 没有：执行 turn_last_resort，调用边界感知转向。
    • 若已经在转向容差内却仍没有可执行平移动作：记录一次 navigation noop；连续 2 次后重新定位，避免原地循环。
  • 动作后是否需要重定位？
    • pose 置信度变 LOW，或累计动作数达到 relocalize_after_actions：执行 localize_scan()。
    • 定位失败：进入 no-tag 恢复判断。
    • 重新定位确认前进无进展：设置/处理碰撞恢复状态。
  • 80 个导航步仍未到达：记录 navigate_failed，上层将该目标标记为 FAILED，不再选择。

4.2 路径规划与 waypoint 选择

plan_navigation_path()
  • action_planner_enabled=True：优先调用 action-level A*。搜索状态包含网格位置和离散 yaw；当前 yaw bin 为 15°。
  • action-level A* 使用前进约 28cm、平移约 12cm、小转和大转作为规划动作；前进/平移基础代价均为 1，转向代价为 1.1cm/deg + 8cm，大转额外增加 4cm，并叠加障碍 cost。
  • 规划段 cost 超过 85 时不能使用；目标容差为 8cm；最大展开数为 45000。
  • action-level A* 找不到路线：回退到地图普通 A*，不会直接盲走。
  • 只有关闭 action planner 时，才比较普通 A* 与“先前进再横移 / 先横移再前进”的直角平移候选；候选必须全程可通行，且长度不超过 A* 的 1.45 倍。
select_navigation_waypoint()
  • 路径为空：直接把 target_xy 当 waypoint。
  • 离最终目标不超过基础前视距离 14cm：直接选最终目标。
  • 跳过离当前 pose 不超过 1cm 的无意义小点，并过滤与当前 pose 不直线可达的点。
  • 动态最大前视距离根据 pose 置信度计算：reserve_stop_distance + forward_step × max_forward_cycles + 16cm buffer。
  • HIGH/MEDIUM/LOW pose 分别最多预看 8/4/2 个前进周期；置信度越低，选择的 waypoint 越保守。
  • 优先返回达到基础前视距离且确实能产生前进、平移或转向动作的最远安全点；否则回退到最后一个可执行点、最后一个直线安全点或首个路径点。

4.3 单步动作选择

world delta → robot-local components forward = dx·cos(yaw) + dy·sin(yaw) lateral = -dx·sin(yaw) + dy·cos(yaw) progress = current_distance_to_waypoint - predicted_distance_after_action choose max(progress); equal progress prefers forward
choose_translation_action(pose, waypoint)
  • 前进候选
    • 机器人坐标系中的 forward 分量至少为 translation_min_forward_cm=6cm。
    • 按剩余距离、14cm 预留停车距离和 pose 置信度计算实际 forward_fast 周期数；当前每周期模型位移约 3.5cm。
    • 计划前进达到 16cm 时执行地图/边界前向检查；更短动作仍会受后续边界和恢复逻辑保护。
    • 预测动作必须让 waypoint 至少接近 translation_min_progress_cm=2cm，否则不生成候选。
  • 左/右平移候选
    • lateral 绝对值至少为 strafe_min_lateral_cm=7cm。
    • 目标不能明显在身后：forward 必须不小于 -8cm；目标 yaw 差必须不超过 115°。
    • 根据 lateral 正负选择 strafe_left_fast 或 strafe_right_fast；每周期模型横移约 4cm。
    • HIGH/MEDIUM/LOW pose 最多执行 6/4/2 个横移周期；预测横移线段必须可通行，并至少产生 2cm 进展。
  • 候选裁决：从有效前进/平移候选中选择预测 progress 最大者；进展相同时优先前进。
  • 执行平移：平移候选直接调用 move_lateral()，清零前进地图阻塞计数。
  • 执行前进前：检查前方障碍 Tag（仅 obstacle 功能启用时）和本次预计前进路径；发现风险则恢复或重新定位，不执行该次前进。
  • 前进后记录期望位移；若视觉进展检查启用，会比较动作前后画面。当前 JSON 中碰撞恢复和 obstacle 检测关闭，但代码路径及配置开关仍保留。

5. 到达当前目标后才分类

ARRIVED_AT_TARGET → CAPTURE_TARGET_SCREEN
  • classifier_gate_open(screen) 同时要求：已到达、screen 是锁定目标、MissionState 属于到达/捕获/分类状态。
  • 在目标地点重新拍照和定位，调用 crop-enabled 屏幕检测。
  • 画面中的候选必须满足 candidate.screen_id == current_target_screen_id；其他屏幕只被忽略，绝不写入当前目标。
  • CLASSIFY_TARGET_FLOWER 仅此函数调用 ClassifierClient.classify_crop()，保留置信度、投票和重拍结构。
  • 没有当前目标绑定、HTTP/结果失败、低置信或票数不足：有限拍摄结束后失败，不编造类别、不进入换花。
  • 稳定结果 == target_flower？
    • 是：ALREADY_TARGET，不举手、不请求 Worker，作为已处理完成。
    • 否：NEEDS_CHANGE，才进入实体接近。

7. 模式、安全选项和结束

入口当前语义
--mode mission完整最近目标循环；无未处理目标时 MISSION_COMPLETE。
--mode localize只执行原初始定位并退出；几何绑定不会分类。
--mode harvest定位后选择最近目标、导航并通过到达门后只分类该目标；不执行实体换花。
--dry-run不连接相机、动作组、FPGA 或 Worker。
--skip-change / --skip-api真实定位/视觉/分类/导航与对准，但模拟举手和 Worker 事务。
